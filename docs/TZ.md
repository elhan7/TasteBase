# Техническое задание: Книга рецептов «TasteBase»

## 1. Описание проекта и бизнес-ценность
TasteBase — это минималистичное веб-приложение для управления личными рецептами. Проект решает проблему «паралича выбора» (когда пользователь не знает, что приготовить). Главная ценность — возможность быстро зафиксировать рецепт и в один клик получить случайное блюдо на ужин из своей же базы.

## 2. Пользовательские сценарии (Use Cases)
* **UC-1: Просмотр каталога.** Пользователь открывает главную страницу и видит список всех добавленных блюд.
* **UC-2: Добавление рецепта.** Пользователь заполняет форму (название, ингредиенты, шаги приготовления) и сохраняет её.
* **UC-3: Случайный выбор.** Пользователь нажимает кнопку «Рандом» и система отображает один случайный рецепт из базы.

## 3. Функциональные требования
* Реализация REST API для взаимодействия фронтенда и бэкенда.
* Валидация входных данных: название рецепта и список ингредиентов не могут быть пустыми.
* Динамическое обновление интерфейса без перезагрузки страницы.

## 4. Нефункциональные требования
* **Время отклика:** Обработка запросов на бэкенде не должна превышать 150 мс.
* **Архитектура:** Разделение Go-кода на независимые слои (Handlers для HTTP, Service для бизнес-логики, Models для структур данных).
* **Логирование:** Вывод ошибок сервера в консоль (stdout).

## 5. Технологический стек
* **Backend:** Язык Golang (фреймворк Gin-Gonic для маршрутизации).
* **Frontend:** Чистый JavaScript (Vanilla JS), HTML5, CSS3. Взаимодействие через Fetch API.
* **Хранилище:** InMemory Storage (структура данных Map в оперативной памяти с блокировками sync.RWMutex).
